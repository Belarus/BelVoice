# Мадэль пастаноўкі націску ў невядомых словах

Нейрасеткавая мадэль для пазначэння націску ў беларускіх словах, якіх няма ў
слоўніку GrammarDB (`StressNoHomographs`/`StressStat`).

## Ідэя

Пастаноўка націску пастаўлена як **класіфікацыя, а не генерацыя**: мадэль чытае
слова цалкам (char-level), а потым softmax выбірае адну з пазіцый **толькі
сярод галосных літар** ("pointer-softmax"). Гэта гарантуе заўсёды карэктны
выхад (немагчыма паставіць націск на зычную ці атрымаць 0/2 націскі) і дае
натуральную ацэнку ўпэўненасці.

## Дадзеныя (`stress.list`)

Файл экспартаваны з GrammarDB (`tools/export_grammardb/.../ExportStressML.java`)
у фармаце:

```
PDG_ID:форма1;форма2;...;формаN
```

дзе `PDG_ID` - id парадыгмы/лемы, а націск пазначаны камбінавальным акутам
`U+0301` адразу пасля націскной галоснай. Гэта важна для навучання:

- **Дэфісныя словы разбіваюцца на сегменты** па дэфісе (`з-пад` → `з`, `пад`;
  `абы-хто́` → `абы`, `хто́`). Праверка па ўсім карпусе паказала, што кожны
  сегмент з галоснай мае роўна адзін націск - гэта значыць, што асобная
  "галава" для другаснага націску (для складаных слоў тыпу
  `во́дазабеспячэ́нне`) **не спатрэбілася**: разбіццё на дэфісныя сегменты ўжо
  вырашае гэтую задачу.
- **Амографы** (адна і тая ж форма з розным націскам у розных лемах, напр.
  `му́зыка`/`музы́ка`) немагчыма трэніраваць без кантэксту - яны **цалкам
  выключаюцца з навучання** і трапляюць у асобны eval-slice (top-1/top-2
  дакладнасць - гл. метрыкі ніжэй).
- **Разбіццё train/val/test робіцца па `PDG_ID` (lemma-disjoint), а не па
  асобных словаформах.** Інакш формы адной лемы (`сталы́`/`стало́м`/`стала́мі`)
  разышліся б па розных спрытах, і дакладнасць на "невядомых словах" была б
  моцна завышанай.
- Прыклады ўзважваюцца як `1/√(колькасць формаў у лемы)`, каб вялікія
  парадыгмы (дзеясловы з 40 формамі) не задушылі малыя (нязменныя прыслоўі).

Дадзеных дастаткова, каб трэніраваць мадэль з нуля - ніякія прэтрэніраваныя
LLM/эмбэдынгі не патрэбныя.

## Архітэктура (`framework/belvoice/synth/stress/StressML_model.py`)

`StressML_model` - char-Transformer энкодэр (6 слаёў, `d_model=256`, 8 галоў),
агульны для навучання і inference:

- **Выраўноўванне па канцы слова** (left-padding): слова падаецца так, каб
  апошні сімвал заўсёды стаяў на адной і той жа пазіцыі, незалежна ад даўжыні
  слова ў пакеце. Націск у беларускай мове - гэта пераважна функцыя суфікса і
  флексіі, а не пачатку слова, таму суфіксы розных па даўжыні слоў дзякуючы
  такому выраўноўванню трапляюць на аднолькавыя пазіцыі, і мадэль вучыць адно
  агульнае правіла замест N варыянтаў для кожнай даўжыні.
- Дзве пазіцыйныя эмбэдынгі: `pos_rev` (адлегласць да канца слова - асноўная,
  не залежыць ад даўжыні пакета дзякуючы left-padding) і `pos_fwd` (адлегласць
  ад пачатку - для прэфіксаў тыпу `най-`, `пера-`).
- Softmax толькі па пазіцыях галосных (`-inf` на астатніх пазіцыях).

## Навучанне (`tools/stress_ml/train.py`)

```bash
pip install -e /home/alex/gits/BelVoice
pip install -r tools/stress_ml/requirements.txt
python tools/stress_ml/train.py --stress-list tools/stress_ml/stress.list
```

- AdamW + cosine LR з warmup, label smoothing 0.1.
- **Аугментацыя "шум у корань":** падчас навучання ў частцы прыкладаў
  выпадкова псуюцца 2-4 сімвалы ў пачатку слова (не чапаючы суфікс і
  націскную галосную) - мадэль вымушана вывесці правіла флексіі замест
  запамінання канкрэтных каранёў, што рэальна дапамагае на невядомых словах.
- **EMA вагоў** (decay 0.999) - фінальная мадэль усярэднена па апошніх кроках,
  без асобнага ансамбля.
- **Early stopping** па дакладнасці на lemma-disjoint val-спрыце (толькі
  нетрывіяльныя словы - гл. метрыкі).
- Вынік навучання (`stress_ml.safetensors` + `stress_ml_config.json` з
  гіперпараметрамі і char-vocab) захоўваецца **напрамую ў**
  `framework/belvoice/synth/stress/` - адтуль яго чытае `StressML`.

Прамежкавы разабраны корпус кэшуецца ў `tools/stress_ml/.corpus_cache.pkl`
(`--rebuild-cache`, каб перабудаваць). Для хуткага smoke-тэсту ёсць
`--max-lines N`.

### Метрыкі, якія друкуюцца пасля навучання

| Slice                                        | Што паказвае                                                      |
|----------------------------------------------|-------------------------------------------------------------------|
| Train (памяткавая sanity-мяжа)               | верхняя мяжа/sanity-праверка (мадэль бачыла гэтыя словы)          |
| **Val/Test (lemma-disjoint), нетрывіяльныя** | **галоўны лік**: дакладнасць на невядомых лемах                   |
| Амографы (top-1 / top-2)                     | межа магчымага без кантэксту (не трэніруецца, толькі ацэньваецца) |
| Test @ confidence ≥ 0.9 + coverage           | для порогу ў продакшне (гл. ніжэй)                                |

"Нетрывіяльнае" слова - слова з ≥2 галоснымі і без `ё` (аканне/яканне робіць
астатнія выпадкі трывіяльнымі дзякуючы беларускай арфаграфіі).

## Выкарыстанне (`framework/belvoice/synth/stress/StressML.py`)

Клас `StressML` пабудаваны па ўзоры `StressStat`/`StressNoHomographs`
(`process_word`, `apply_stresses(text)`, той жа `WORD_PATTERN`/`\u0301`):

```python
from belvoice.synth.stress import StressML

text = StressML().apply_stresses("Ён адказаў ?")
```

`torch`/`safetensors` наўмысна **не дадаваныя ў залежнасці BelVoice**
(`pyproject.toml`) - гэта апцыянальная функцыянальнасць, яе трэба ўсталяваць
асобна (`pip install -r tools/stress_ml/requirements.txt`).

### Гібрыдная схема

`StressML` прызначаны перадусім для **OOV**-слоў - словы, вядомыя ў
`StressNoHomographs`/`StressStat`, лепш браць адтуль:

```
слова → пошук у слоўніку (StressNoHomographs/StressStat) ─── знайшлося → адказ
                                                        └── OOV → StressML → адказ + confidence
```

`process_word()` вяртае і слова з націскам, і `confidence` (мінімальную
ўпэўненасць сярод дэфісных частак) - можна выкарыстоўваць для адпраўкі на
ручную праверку слоў з нізкай упэўненасцю.
