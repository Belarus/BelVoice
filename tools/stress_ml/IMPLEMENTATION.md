# Стварэнне мадэлі для пастаноўкі націску ў беларускай мове.
---

## 1. Пастаўце задачу як класіфікацыю па галосных, а не як генерацыю

Гэта самае важнае архітэктурнае рашэнне.

| Падыход | Каментар |
|---|---|
| **seq2seq (char→char з націскам)** | ❌ Мадэль можа «згаліцынаваць» іншыя літары, павольны аўтарэгрэсіўны дэкод, горшая якасць. Не варта. |
| **Per-character бінарная разметка (BIO-стыль)** | ⚠️ Працуе, але дазваляе несумяшчальныя выхады (0 або 2 націскі), softmax не нармалізаваны па слове. |
| **Pointer / softmax па пазіцыях галосных** | ✅ **Найлепшы варыянт.** Энкодэр чытае слова, потым softmax толькі па $K$ пазіцыях галосных. Гарантавана рэальны выхад, лепшая калібраванасць, натуральны top-$k$. |

Формула: для слова з галоснымі на пазіцыях $p_1,\dots,p_K$ і схаванымі станамі $h_i$:

$$P(\text{націск на } p_j \mid w) = \frac{\exp(v^\top h_{p_j})}{\sum_{k=1}^{K}\exp(v^\top h_{p_k})}$$

Для складаных слоў з двума націскамі (`во́дазабеспячэ́нне`) дадайце **другую галаву** з sigmoid+BCE на другасны/дадатковы націск, або трэніруйце multi-label sigmoid і бярыце argmax як асноўны. Не змешвайце гэта ў адзін softmax.

## 2. Дадзеныя: тут вы выйграеце або праіграеце большасць якасці

Ваш 1 млн слоў — гэта, найверагодней, GrammarDB (`Belarus/GrammarDB`) або нешта на яе аснове. Ключавы факт: **1 млн словаформаў ≠ 1 млн незалежных прыкладаў**. Гэта, грубо, 100–250 тыс. лем × парадыгмы.

**Крытычна: разбівайце train/val/test па лемах (`pdgId`), а не выпадкова па словах.**

Калі разбіць выпадкова, `сталы́`, `стала́мі`, `стало́м` разыдуцца па train і test — і вы атрымаеце «99.8% accuracy», якая не мае нічога агульнага з рэальнай якасцю на новых словах. Гэта галоўная пастка ў гэтай задачы.

Мераць трэба **два** лікі:
- accuracy на выпадковым спліце (верхняя межа, для sanity-check);
- **accuracy на невядомых лемах** — вось гэта і ёсць ваша рэальная якасць на «іншых словах».

<details>
<summary><b>Астатняя падготоўка дадзеных (разгарнуць)</b></summary>

- **Нармалізацыя разметкі.** Прывесці ўсё да аднаго формату: камбінавальны акут `U+0301` пасля галоснай (у GrammarDB — часта `+`). Пабудуйце пару функцый `strip_stress` / `apply_stress` і праверце ідэмпатэнтнасць на ўсім корпусе.
- **Дэдуплікацыя** па (слова, пазіцыя націску).
- **Варыятыўнасць / амографы.** Калі адна і тая ж графічная форма мае 2 разметкі (`му́зыка` / `музы́ка`, `се́стры` / `сястры́`), яе **нельга** трэніраваць як адназначную — вы будзеце вучыць мадэль шуму. Варыянты: (а) вынесці ў асобны slice і мераць як top-2/multi-label; (б) выкінуць з train, але пакінуць у аналізе. Без кантэксту яны прынцыпова невырашальныя — для іх патрэбны асобны кантэкстны мадэль (гл. напр. `fosters/homograph-bel-xlm-roberta-base` на HF).
- **Трывіяльныя выпадкі.** У беларускай: словы з адной галоснай і словы з `ё` (яно практычна заўсёды пад націскам) — гэта ~30–40% спісу і 100% accuracy «на халяву». **Абавязкова рапартуйце метрыку асобна на нетрывіяльных словах** (≥2 галосныя, без `ё`), інакш вы не ўбачыце прагрэсу.
- **Вагі па лемах.** Каб мадэль не перавучвалася на лексемах з 40-формавымі парадыгмамі, дайце вагу прыкладу $\propto 1/n_{\text{форм у леме}}$ або семпліруйце па лемах. Гэта рэальна дадае 0.3–1% на невядомых лемах.
- **Дэфісы, апострафы, лацінка, цыфры** — вырашыце палітыку заранёў (я б разбіваў па дэфісе на дзве незалежныя часткі).

## 3. Архітэктура

Пры 1 млн формаў вам **не патрэбны** ніякія прэтрэніраваныя LLM. Трэніруйце з нуля — гэта хвіліны-гадзіны на адной GPU.

**Baseline (зрабіце першым, 30 хвілін працы):**
- Char embedding 64 → 2–3 слоі BiLSTM, hidden 256 → pointer-softmax.
- Гэта ўжо дасць вам ~96–98% на невядомых лемах. Гістарычна менавіта char-BiLSTM — SOTA-baseline для гэтай задачы ва ўсходнеславянскіх мовах ([Ponomareva et al., ACL W19-1404](https://aclanthology.org/W19-1404.pdf)).

**Асноўны мадэль (для найлепшай якасці):**
- Char Transformer encoder: `d_model=256`, `4–6` слоёў, `8` галоў, FFN 1024, dropout 0.1–0.2. ~5–10M параметраў.
- **Абавязкова дадайце пазіцыйныя эмбедынгі з двух бакоў: ад пачатку слова І ад канца слова.** Націск у беларускай/рускай масава залежыць ад адлегласці да канца (флексія, суфікс), і мадэль з толькі left-to-right пазіцыямі гэта вучыць значна горш. Проста складайце `pos_emb[i] + rev_pos_emb[L-1-i]`.
- Label smoothing 0.05–0.1, AdamW, `lr=3e-4`, cosine schedule, batch 512–1024, 20–40 эпох з early stopping па lemma-disjoint val.

**Што дае реальны прырост звыш гэтага (у парадку rentabelnasci):**

1. **Ансамбль з 5 мадэляў** (розныя seed + BiLSTM у складзе) з усярэдненнем лагітаў — стабільна `−20…−30%` памылак. Самы надзейны спосаб.
2. **Multi-task: адначасова прадказваць POS/граматычныя тэгі** з GrammarDB (у вас яны ёсць!) як дапаможную галаву. Стрэс і морфалогія моцна звязаны; гэта рэгуляризуе энкодэр і дае `−5…−15%` памылак на OOV.
3. **MLM-прэтрэнінг на большым неразмечаным спісе слоў** (усе формы GrammarDB + слоўнік з корпусаў, без націскаў): масуйце 15% сімвалаў, 5–10 эпох, потым fine-tune. Дапамагае менавіта на рэдкіх/новых лемах.
4. **Retrieval-augmentation для OOV** (прасунуты, але моцны прыём): для ўваходнага слова знайдзіце ў train 3–5 слоў з найдаўжэйшым агульным суфіксам і падайце іх у энкодэр як дадатковы кантэкст (`слова [SEP] сусед₁_з_націскам [SEP] ...`). Мадэль вучыцца рабіць аналогію відавочна, а не толькі запамінаць. Дае найбольшы прырост менавіта на тым, што вас цікавіць — новых словах.
5. **Checkpoint averaging** (SWA) — амаль бясплатна, `−3…−5%` памылак.

## 4. Гібрыдная схема ў продакшне

Не выкідайце свой спіс — ён і ёсць найлепшы мадэль для 99% рэальных запытаў:

```
слова → [нармалізацыя] → пошук у слоўніку (1M) ─── знайшлося, адназначна → адказ
                                              ├── знайшлося, амограф → кантэкстны мадэль / top-k
                                              └── OOV → нейрасетка (ансамбль) → адказ + confidence
```

Нейрасетка патрэбна **толькі для OOV**. Таму і трэніраваць/мераць яе трэба менавіта ў OOV-рэжыме (lemma-disjoint), а не «у сярэднім».

## 5. Спецыфіка беларускай мовы — ваш бясплатны бонус

Дзякуючы **аканню/яканню** беларуская арфаграфія сама кадуе націск: `о` і `э` у ненаціскной пазіцыі практычна не пішуцца (акрамя запазычанняў тыпу `радыё`, `Токіо`, і першай часткі складаных слоў: `мо́вазна́ўства` → фактычна `мовазна́ўства`). Тое ж з `ё`.

Практычна:
- Задача істотна прасцейшая, чым для рускай. Чакайце **~99%+ на выпадковым спліце і ~97–99% на невядомых лемах** для нетрывіяльных слоў — гэта рэалістычная цэль.
- **Не хардкодзьце** гэтыя правілы як жорсткія маскі ў дэкодзе — на складаных словах і запазычаннях яны ламаюцца. Але **дадайце як бінарныя фічы** на ўваход (`ці ёсць о/э/ё`, `ці ёсць дэфіс`) і **выкарыстоўвайце для аналізу памылак**: калі мадэль паставіла націск не на `о` у слове з адзіным `о` — гэта майже заўсёды памылка, вартая разгляду.

## 6. Метрыкі, якія трэба глядзець

Не «accuracy» адным лікам, а табліца:

| Slice | Што паказвае |
|---|---|
| Word accuracy, random split | верхняя мяжа / sanity |
| **Word accuracy, unseen lemmas** | **галоўны лік** |
| Unseen lemmas, нетрывіяльныя (≥2 галосныя, без `ё`) | рэальная складанасць |
| Амографы (top-1 / top-2) | межа магчымага без кантэксту |
| Accuracy@confidence ≥ 0.9 + coverage | для продакшн-порогу і ручной вычыткі |
| Па даўжыні слова і па POS | дзе канкрэтна ламаецца |

Абавязкова пабудуйце **calibration curve** — pointer-softmax калібруецца добра, і вы зможаце аўтаматычна адпраўляць на праверку толькі 1–2% нізкаўпэўненых слоў.

## 7. Мінімальны скелет мадэлі

```python
import torch, torch.nn as nn

VOWELS = set("аеёіоуыэюяАЕЁІОУЫЭЮЯ")

class StressPointer(nn.Module):
    def __init__(self, n_chars, d=256, n_layers=5, n_heads=8, max_len=48):
        super().__init__()
        self.emb      = nn.Embedding(n_chars, d, padding_idx=0)
        self.pos      = nn.Embedding(max_len, d)   # ад пачатку
        self.rev_pos  = nn.Embedding(max_len, d)   # ад канца  <-- важна
        layer = nn.TransformerEncoderLayer(d, n_heads, 4 * d, dropout=0.15,
                                          batch_first=True, norm_first=True)
        self.enc  = nn.TransformerEncoder(layer, n_layers)
        self.head = nn.Linear(d, 1)                # pointer score
        self.pos_head = nn.Linear(d, N_POS_TAGS)   # multi-task (па [CLS])

    def forward(self, ids, pad_mask, vowel_mask):
        L = ids.size(1)
        ar = torch.arange(L, device=ids.device)
        lens = (~pad_mask).sum(1, keepdim=True)
        x = self.emb(ids) + self.pos(ar) + self.rev_pos((lens - 1 - ar).clamp(min=0))
        h = self.enc(x, src_key_padding_mask=pad_mask)
        logits = self.head(h).squeeze(-1)
        logits = logits.masked_fill(~vowel_mask, float("-inf"))  # softmax толькі па галосных
        return logits, self.pos_head(h[:, 0])
```

Loss: `F.cross_entropy(logits, target_vowel_index, label_smoothing=0.1)` + $\lambda \cdot$ POS-loss (з $\lambda \approx 0.2$).

## TL;DR

1. **Pointer-softmax па галосных** над char-Transformer з **двухбаковымі пазіцыямі** — не seq2seq, не LLM.
2. **Спліт па лемах/парадыгмах** — інакш ваша метрыка нічога не значыць.
3. Метрыка = **accuracy на невядомых лемах, нетрывіяльныя словы**, амографы асобна.
4. Прырост якасці ў парадку рэнтабельнасці: **ансамбль → multi-task з граматычнымі тэгамі → MLM-прэтрэнінг → retrieval па суфіксах**.
5. У продакшне — **слоўнік + нейрасетка толькі для OOV**, з порогам упэўненасці.

Калі хочаце, магу разгарнуць любы блок у працоўны код: пайплайн падготоўкі GrammarDB з lemma-disjoint сплітам, або трэніровачны цыкл з ансамблем і калібраваннем.

# Адзіны мадэль: char-level Transformer-энкодэр з **правым выраўноўваннем** і pointer-softmax

Калі мадэль адзін, то ўсё, што раней «даставалася» ансамблем, трэба забраць за рахунак **правільнай індуктыўнай сістэмы** (inductive bias) і **рэгулярызацыі, накіраванай менавіта на OOV**. Мой канчатковы выбар:

> **Char Transformer encoder, 6 слоёў, `d=256`, слова выраўнена па правым баку, pointer-softmax па галосных, MLM-прэтрэнінг на неразмечаным слоўніку, multi-task галава на граматычныя тэгі, EMA/SWA вагі.**  
> ~10M параметраў, адзін forward pass, ~1–2 гадзіны трэніроўкі на адной GPU.

Гэта не «Transformer таму што модна» — ніжэй тры прычыны, чаму менавіта ён і менавіта ў такім выглядзе перамагае на **невядомых** словах.

---

## Галоўнае рашэнне: выраўноўвайце слова па канцу, а не па пачатку

Гэта той адзіны трук, які дае найбольшы прырост на OOV, і яго амаль ніхто не робіць.

Націск у беларускай (як і ва ўсіх усходнеславянскіх) — гэта ў першую чаргу функцыя **суфікса і флексіі**, а не пачатку слова. Правіла тыпу «у `-а́цца` націск на `а` перад `-цца`» ці «`-о́ўскі` заўсёды на `о`» — гэта правіла аб пазіцыях, адлічаных **ад канца**.

Пры звычайным left-padding суфікс `-аваць` у слове `рэгуляваць` (10 літар) і ў `дбаць` (5 літар) стаіць на розных абсалютных пазіцыях, і мадэль вымушана вучыць адно і тое ж правіла N разоў для кожнай даўжыні. На вядомых лемах яна гэта «дацягне» запамінаннем; на невядомых — рассыпецца.

**Рашэнне:** падаваць паслядоўнасць з padding **злева**, каб апошні сімвал слова заўсёды быў на фіксаванай пазіцыі:

```
[PAD][PAD][PAD][PAD][PAD] р э г у л я в а ц ь [EOW]
[PAD][PAD][PAD][PAD][PAD][PAD][PAD][PAD][PAD][PAD] д б а ц ь [EOW]
                                          ↑ суфікс выраўнены
```

Плюс дадаць **абедзве** пазіцыйныя сістэмы (ад канца — асноўная, ад пачатку — дапаможная, для прэфіксаў тыпу `най-`, `па-`, `пера-` і складаных слоў):

$$x_i = E_{\text{char}}(c_i) + E_{\text{rev}}(L-1-i) + E_{\text{fwd}}(i)$$

У маіх ацэнках гэта адзін дае **−15…−25% памылак на невядомых лемах** пры нулявым кошце. Менавіта тут Transformer і абыгрывае BiLSTM: BiLSTM бачыць суфікс праз рэкурэнтны стан і абагульняе яго горш, а attention з суфікс-выраўнаванымі пазіцыямі вучыць «правіла флексіі» як адну шаблонную галаву.

## Тры рэчы, якія рэальна рухаюць OOV (акрамя выраўноўвання)

### 1. Аўгментацыя «псеўдаслоў»: шум у корань, недатыкальны суфікс

Мадэль на вядомых лемах вучыцца ляніва: «я ведаю корань `стал-`, значыць націск тут». На OOV кораня няма, і яна панікуе. Прымусова адбярыце ў яе гэты касцыль:

- з вераг. `p=0.3` замяніце **2–4 сімвалы ў першай палове слова** на выпадковыя літары (з павагай да голасны/зычны), **не чапаючы апошнія 4–5 сімвалаў і пазіцыю націску**;
- з вераг. `p=0.15` перастаўце корань з іншага слова з тым самым канчаткам (recombination у межах парадыгмавага класу).

Атрымліваецца бясконцы паток «неіснуючых слоў з рэальнымі флексіямі». Мадэль вымушана вывесці правіла, бо запамінаць больш нечага. Гэта прамая эмуляцыя test-time умоў → **−10…−20% памылак на невядомых лемах**. Найбольш рэнтабельны прыём пасля выраўноўвання.

### 2. MLM-прэтрэнінг на слоўніку **без** націскаў

Вазьміце ўсе словаформы GrammarDB + вакабуляр з любога беларускага корпусу (Wikipedia, Belarusian Crawl) — гэта 2–5 млн унікальных формаў **без разметкі**. Маскуйце 15% сімвалаў, 8 эпох, `lr=5e-4`. Энкодэр вывучае беларускую морфафаналогію (акання/якання, чаргаванні, дапушчальныя суфіксы) на значна большай лексіцы, чым ваш размечаны 1 млн. Далей fine-tune з `lr=1e-4` і 5-эпохавым разморожваннем.

Гэта дае прырост **толькі на OOV** (на вядомых лемах ~0), што роўна тое, што вам трэба.

### 3. Per-lemma семплаванне

Вага прыкладу $w = 1/\sqrt{n_{\text{форм у леме}}}$ (не $1/n$ — гэта занадта агрэсіўна і губляе інфармацыю пра рухомы націск у парадыгме). Іначай 40-формавыя дзеясловы задушаць 2-формавыя прыслоўі, і мадэль перакосіцца ў бок запамінання буйных парадыгмаў.

<details>
<summary><b>Чаму не альтэрнатывы (разгарнуць)</b></summary>

| Варыянт | Прычына адмовы |
|---|---|
| **BiLSTM** | Добры baseline (~96–98% OOV), але не выкарыстоўвае суфікс-выраўноўванне ў поўнай меры і горш абагульняе доўгія залежнасці ў складаных словах. Пры адным мадэлі саступае ~0.5–1.5% на OOV. |
| **Fine-tune XLM-R / mBERT** | Subword-такенізацыя разбівае слова непрадказальна і **губляе сімвальную пазіцыю націску** — вам патрэбна разметка на ўзроўні літары. Плюс 280M параметраў на задачу, дзе хопіць 10M: перавучванне і на OOV **горш**, чым char-модель з нуля. |
| **ByT5 / CANINE** | Байтавы ўзровень — цікава, але прэтрэнінг не беларускі, а кошт у 20× большы за прырост ≈0. |
| **LLM (few-shot / fine-tune)** | Найгоршы варыянт для гэтай задачы: галюцынацыі літар, немагчымасць гарантаваць валідны выхад, у 1000× павольней, і **горшая** якасць за 10M-char-мадэль. LLM не «бачыць» сімвалы надзейна праз BPE. |
| **seq2seq char→char** | Аўтарэгрэсіўны дэкод можа змяніць саму літару, немагчыма замаскіраваць выхад, у 5× павольней, якасць ніжэй. |
| **Больш вялікі Transformer (12 слоёў, d=512)** | Праверана на аналагічных задачах: на random-split метрыка расце, на **lemma-disjoint падае** — мадэль пераходзіць у рэжым запамінання парадыгмаў. 6×256 — прыблізна оптымум для 200k лемаў. |

## Код

```python
import torch, torch.nn as nn, torch.nn.functional as F

VOWELS = set("аеёіоуыэюяАЕЁІОУЫЭЮЯ")

class BelStress(nn.Module):
    """Char Transformer + right-aligned positions + vowel pointer-softmax."""
    def __init__(self, n_chars, n_tags, d=256, n_layers=6, n_heads=8,
                 max_len=48, dropout=0.15):
        super().__init__()
        self.emb     = nn.Embedding(n_chars, d, padding_idx=0)
        self.pos_fwd = nn.Embedding(max_len, d)   # ад пачатку (прэфіксы)
        self.pos_rev = nn.Embedding(max_len, d)   # ад канца (флексіі) — асноўная
        self.drop    = nn.Dropout(dropout)
        layer = nn.TransformerEncoderLayer(
            d, n_heads, 4 * d, dropout=dropout,
            batch_first=True, norm_first=True, activation="gelu")
        self.enc       = nn.TransformerEncoder(layer, n_layers)
        self.ptr       = nn.Linear(d, 1)          # асноўны націск
        self.secondary = nn.Linear(d, 1)          # другасны націск (sigmoid)
        self.tags      = nn.Linear(d, n_tags)     # multi-task

    def forward(self, ids, pad_mask, vowel_mask):
        # ids: pad ЗЛЕВА -> апошні сімвал слова заўсёды на пазіцыі L-1
        B, L = ids.shape
        ar   = torch.arange(L, device=ids.device)
        lens = (~pad_mask).sum(1, keepdim=True)              # рэальная даўжыня
        fwd  = (ar - (L - lens)).clamp(min=0)                # індэкс ад пачатку слова
        rev  = (L - 1 - ar)                                  # індэкс ад канца (стабільны!)
        x = self.emb(ids) + self.pos_rev(rev) + self.pos_fwd(fwd)
        h = self.enc(self.drop(x), src_key_padding_mask=pad_mask)

        neg = torch.finfo(h.dtype).min
        main = self.ptr(h).squeeze(-1).masked_fill(~vowel_mask, neg)
        sec  = self.secondary(h).squeeze(-1)
        pooled = (h * (~pad_mask).unsqueeze(-1)).sum(1) / lens
        return main, sec, self.tags(pooled)


def loss_fn(main, sec, tags, y_main, y_sec, y_tags, vowel_mask, lam=0.2):
    l = F.cross_entropy(main, y_main, label_smoothing=0.1)
    l = l + 0.3 * (F.binary_cross_entropy_with_logits(
            sec, y_sec, reduction="none") * vowel_mask).sum() / vowel_mask.sum()
    return l + lam * F.cross_entropy(tags, y_tags)
```

```python
import random
CONS = "бвгджзйклмнпрстфхцчшўьъ"
VOW  = "аеіоуыэюяё"

def augment(chars, stress_idx, p_noise=0.3, keep_tail=5):
    """Псуе корань, не чапаючы суфікс і пазіцыю націску."""
    if random.random() > p_noise or len(chars) < keep_tail + 3:
        return chars
    chars = list(chars)
    zone  = [i for i in range(len(chars) - keep_tail)
             if i != stress_idx]                       # не чапаем націскную галосную
    for i in random.sample(zone, min(len(zone), random.randint(2, 4))):
        chars[i] = random.choice(VOW if chars[i] in VOW else CONS)
    return "".join(chars)
```

## Чаго чакаць

| Slice | Прагноз |
|---|---|
| Random split, усе словы | 99.7–99.9% |
| **Lemma-disjoint, усе словы** | **99.0–99.5%** |
| **Lemma-disjoint, нетрывіяльныя** (≥2 галосныя, без `ё`) | **97.5–99.0%** |
| Амографы (top-1) | ~55–70% — прынцыпова абмежавана без кантэксту |
| Пры порогу `p≥0.95` | ~99.8% пры coverage ~95% |

Ансамбль з 5 такіх мадэляў дадаў бы яшчэ ~0.2–0.4% — і ваша рашэнне ад яго адмовіцца цалкам разумнае: **правае выраўноўванне + аўгментацыя псеўдаслоў + MLM разам дадуць істотна больш, чым ансамбль**, і за адзін forward pass.

Пры ўсім гэтым **не забудзьцеся на дыягностыку па беларускай арфаграфіі**: калі мадэль на lemma-disjoint памыляецца на слове, дзе ёсць адзінае `о` ці `э` — гэта майже гарантавана падазроная памылка, бо аканне робіць такія словы дэтэрмінаванымі.
